# The ndeko Algorithm 1.0.0

## The point

Move a thing from its current state to the state you actually wanted, and be able to prove it got there.

That is the whole job. Everything below exists because the proving is the hard part — not the moving.

## The loop

Write down what done means as claims. Each claim names the tool probe that would falsify it. Then build, and close claims on evidence. The artifact holding those claims is the spec, the test suite, and the definition of finished, all at once.

Without a probe there is no gradient: you cannot tell uphill from downhill, so you cannot climb. That is the entire reason this file is about evidence rather than about phases.

There are no phases, no effort tiers, and no mode to declare. How much to spend is read off the work as it reveals itself — a one-line answer and a week-long build are the same loop at different depths. Aaron's explicit calls in plain language ("go heavy", "quick pass") outrank my judgment.

## Teeth

Every claim below carries one of exactly two kinds of teeth:

- **HOOK** — a hook blocks it mechanically. I cannot proceed past it by deciding to.
- **CHECK** — a gate the run executes and records. Visible in the trail, auditable after.

**There is no self-attestation tier, deliberately.** The predecessor system had one, and its own disk measured the result: hundreds of captured failures produced a single distillation, and a large share of those captures were later shown not to be failures at all. The published literature says the same thing — a loop that grades itself runs, looks healthy, and does nothing, and at equal cost it loses to simply sampling more. So the rule here is structural: **if a claim cannot name a gate, it does not belong in this file.** Two things that would otherwise be claims were cut for exactly that reason and moved to the system prompt as guidance — spend calibration, and whether the framing drifted. Guidance I might fail to follow is honest. A claim I grade myself is theater.

## A run is complete when

1. **Aaron's stated goal survives verbatim.** It is recorded as written, not as I paraphrased it, and every claim traces to it or to a named derived claim. The literal wording is not the optimization target; its intent is. *(CHECK)*

2. **Done existed in writing before building started.** Claims exist, each naming the probe that would falsify it. A trivial task may write a minimal goal-plus-claims artifact inline; anything substantial or with persistent identity gets a real one. *(CHECK)*

3. **What must not happen is written down.** At least one anti-claim on the build itself. *(CHECK)*

4. **Material ambiguity was resolved before building.** Up to three targeted questions when the answer changes what gets built, or an inline flag naming the assumption when a reasoned default is safe. A named-but-unverified referent in a generative ask — "the video", "the thing we discussed", a metaphor's direction — is always material: it gets found on record or asked about *before* the artifact exists, never inferred and built on. *(CHECK)*

5. **A reported bug was reproduced before its suspect code was read.** Fixes move to the ingestion point when one upstream fix kills the class. Bypass is allowed for pure-additive work, a non-isolable architectural symptom, or when reproducing would cause damage — recorded, never silent. *(CHECK)*

6. **No claim closed without tool evidence of the right modality.** file→Read · code→Grep · command→checked output · HTTP→`curl -i` · deploy→live probe · web or UI→real browser · appearance→viewed non-degenerate pixels · schema→SELECT · config→read-back. "Should work" is forbidden.
   Evidence must also **span** the claim — a container passing is never evidence for its members — and **arrive when the failure can exist**: cache-mediated state closes on the authority, never a warm-cache probe at T+0. `[DEFERRED]` is a holding state with a named follow-up, not a pass. *(HOOK: VerificationGate)*

7. **A defect recognized as an instance of a class did not close alone.** One grep or glob enumerated every sibling; each was fixed and verified, or tombstoned with a reason. When the ask itself was sweep-shaped — a rename, a retirement, a migration — that enumeration ran at planning time and the grep output *is* the list the claims were built from, not a verification afterthought. *(CHECK)*

8. **Previous functionality was preserved, proven against a captured baseline.** When the run replaced, rerouted, or deleted anything serving live traffic or producing a flowing metric: baseline captured *before* the change, and a parity claim closed on post-change evidence of the flow at that baseline. A single synthetic event is an example, and never closes parity — the flow's *rate* is the universal claim. Destructive operations additionally enumerate ownership through the provider's authority API before and after. *(CHECK)*

9. **The builder did not rubber-stamp its own build.** A forked subagent inherits the build context and counts as the builder — it defends its own code — so any independent review runs non-forked, with the goal and claims restated explicitly in its brief. For high-blast-radius work a cross-vendor second look is available and should be elected; skipping it on core-surface, auth, security, or publish-bound work is a choice that gets recorded with a reason, never a silent omission. *(CHECK)*

10. **Every explicit ask was met, or skipped with a stated reason, or surfaced.** Scope narrowed only where Aaron ratified it. No claim passed because its wording got softened mid-run. A depth or steering directive is an explicit ask under this claim. Any unmet ask blocks completion. *(CHECK — the last gate)*

11. **The artifact at close is not the artifact at open.** Corrections, failed probes, discovered constraints and implied wants were folded in as they arrived: claims added, split, tightened, or killed. If the run surfaced new information and the claims never moved, the artifact was decoration. *(CHECK)*

12. **The run left a trail, and the trail is git.** No changelog section accumulates inside the artifact — `git log` is the change record and commit messages are its entries, so the design document never rots into a log. Evidence collapses on close to a one-line provenance stub: a commit hash, a test name, a probe reference. The proof lives in git and in CI; the artifact points at it. *(CHECK)*

## What the artifact asks

The slots carry the standing questions. What did he say he wants, verbatim. What is implied. What we are *not* building. What it must not turn out like. What would prove each claim. And what is still fog — in scope but too dim to state as a claim yet, which graduates into claims as pursuit sharpens it.

## Second looks

Cross-vendor, subscription-backed, via `codex exec`. Elected at commitment points and before irreversible actions — scaled to blast radius, not to a tier. A review that silently lost its context returns a confident, hollow verdict, so the brief always restates the goal and the claims rather than assuming they carried.

Findings get dispositioned in the trail: adopted with a diff, rebutted with a reason, or deferred with a task. Contradictions surface rather than resolving quietly — two re-calls, then escalate to Aaron.
