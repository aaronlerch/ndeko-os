# Agent Memory Systems: State of the Art, Mid-2026

Research date: 2026-08-16. Vendor-published numbers are labeled as such because almost none survive independent reproduction.

## 0. The one-paragraph version

The field split in two during 2025–2026. **Managed memory services** (Mem0, Zep, MemOS, Exabase, Hindsight) compete on leaderboards with extraction pipelines, vector stores, and temporal knowledge graphs — and the leaderboard is contaminated by self-run harnesses. **Agent-native memory** (Anthropic's memory tool, Letta Context Repositories, Claude Managed Agents, Manus) converged hard on *files on a filesystem that the agent edits with ordinary tools*, and this is now the position of both major coding-agent vendors. Your architecture is not fringe — it is roughly where Anthropic and Letta independently landed in 2026. The published attacks on it are real but narrow: **multi-user governance, fact-level provenance, concurrency, and semantic (not lexical) recall at scale** — not whether files work.

## 1. Dedicated memory products and libraries

**Mem0** — Two-phase pipeline. *Extraction*: an LLM converts new messages (plus a rolling summary as global context) into atomic candidate facts. *Update*: retrieve top-k similar memories from a vector DB, then an LLM decides `ADD / UPDATE / DELETE / NOOP`. Graph variant (`Mem0^g`) adds entity/relation triplets. Scoped conversation → session → user → org with promotion between layers. ([paper](https://arxiv.org/html/2504.19413v1)) Library + hosted service. Strongest adoption signal in the category: ~60k GitHub stars (July 2026), API calls 35M (Q1 2025) → 186M (Q3 2025), $24M Series A led by Basis Set, exclusive memory provider for the AWS Agent SDK ([PR](https://www.prnewswire.com/news-releases/mem0-raises-24m-series-a-to-build-memory-layer-for-ai-agents-302597157.html)). **Tradeoff:** an LLM call sits on the write path of every memory — you buy automatic distillation and pay in latency, cost, and lossy extraction. The raw episode is gone.

**Zep + Graphiti** — Graphiti is a **bi-temporal** knowledge graph. Entities are nodes, facts are edges, every edge carries four timestamps: `t_created`/`t_expired` (when the system learned/retired it) and `t_valid`/`t_invalid` (when it was true in the world). Superseded facts are **invalidated, not deleted**, so you can reconstruct what the agent believed at any past moment. ([Zep paper](https://storage.ghost.io/c/79/c4/79c4903e-2432-4c0e-b8c8-c8988fef71ec/content/files/2025/01/ZEP__USING_KNOWLEDGE_GRAPHS_TO_POWER_LLM_AGENT_MEMORY_2025011700.pdf), [Neo4j](https://neo4j.com/blog/developer/graphiti-knowledge-graph-memory/)) Graphiti open source; Zep is cloud. Self-hosted Community Edition **retired in 2025** — real adoption risk. Best-in-class at "what was true, and when."

**Letta (formerly MemGPT) — most relevant system to your architecture.** Original: self-editing tiered memory, agent-visible "memory blocks" the model edits via tools, plus archival paging. **February 12, 2026 — Context Repositories:** Letta rebuilt memory for coding agents as **a git repository on the local filesystem**. Files carry YAML frontmatter modeled explicitly on Anthropic's `SKILL.md`. The filetree is always in the system prompt, so *folder hierarchy and filenames are the retrieval index*. Every mutation is an auto-committed git change with a generated message. Subagents each get an **isolated git worktree** and merge memory back through normal git conflict resolution. Agents query memory with bash and scripts. ([Letta](https://www.letta.com/blog/context-repositories/)) ~23.9k stars (July 2026). **They published no benchmark numbers for it** — it's an architectural bet, not a measured win. Also from Letta: *sleep-time compute* (with UC Berkeley) — **~5x reduction in test-time compute for equal accuracy**, **+13% (Stateful GSM-Symbolic) / +18% (Stateful AIME)** when scaled ([arXiv 2504.13171](https://arxiv.org/abs/2504.13171)).

**MemOS** — "Memory OS": L1 traces, L2 policies, L3 world models, crystallized **Skills** for cross-task reuse. Hybrid retrieval, local-first storage, feedback-driven ranking. Vendor-claimed 88.83 LoCoMo, 89.20 LongMemEval, 35.24% token savings, #1 on its own **OmniMemEval** (14 commercial products, 10 datasets) ([GitHub](https://github.com/MemTensor/MemOS)). Most complete conceptual model in open source; also the one whose headline benchmark is its own.

**MemMachine** — explicitly **ground-truth-preserving**: stores raw conversational episodes and *minimizes* routine LLM extraction, layering short-term + episodic + profile memory on top. ~80% token reduction claimed ([arXiv 2604.04853](https://arxiv.org/html/2604.04853v1)). Closest managed system to your philosophy: keep the raw artifact, derive views, don't let an LLM be the lossy gate on the write path.

**A-MEM** — Zettelkasten for agents. Each memory becomes a structured note (context description, keywords, tags); the system analyzes historical notes and **auto-creates links**, evolving the network ([arXiv 2502.12110](https://arxiv.org/pdf/2502.12110)). Your `[[wikilink]]` convention is A-MEM's core idea done manually; A-MEM's contribution is that link formation is an LLM step, not a human one.

**MIRIX** — modular multi-agent memory split into **core, episodic, semantic, procedural, resource memory, and a knowledge vault**, each managed by a dedicated memory agent. Most explicit implementation of the cognitive taxonomy.

**Cognee** — graph-native. `Remember → Recall → Improve → Forget`; an ECL (Extract–Cognify–Load) pipeline builds a Neo4j graph, auto-router picks vector vs graph per query. Broadest integration surface among graph-native options.

**Memobase** — doesn't store fact rows; builds a **structured evolving user profile** refreshed every few interactions, hard cap of exactly 3 LLM calls per run. Positions as a **cross-tool memory passport** over MCP (Claude, Cursor, others share one layer).

**Supermemory** — embeddings + time annotations + ranker blending semantic score with recency. Deliberately not a graph.

**Basic Memory — the closest published system to yours.** Markdown files on local disk are the source of truth; a **SQLite index sits alongside** for speed. Semantic markdown schema — frontmatter, observations, relations encode a knowledge graph in the file. Wikilinks make it natively an Obsidian vault. Hybrid FTS + vector ranking (FastEmbed) on SQLite or Postgres. MCP server, bidirectional human/LLM editing. ([GitHub](https://github.com/basicmachines-co/basic-memory)) **The delta vs your system: they added a derived index and vector ranking without giving up files as truth.** Single most stealable idea in this report.

**LangMem** — LangChain/LangGraph memory primitives at user/thread/namespace scope, MIT. Only worth it if already in LangGraph.
**Honcho** — bets on **stateful social memory**: representations of people and entities plus continual learning, rather than fact storage.
**Memary** — lightweight KG + vector, explicitly for prototyping. **txtai** — general embeddings DB used as memory; no meaningful 2026 agent-memory positioning surfaced.

**New entrants:** **Exabase M-1** — as of 2026-07-28, highest reported BEAM: **76.9% @100K, 75.0% @1M, 68.0% @10M**, ~20% fewer tokens/query than runner-up ([AIwire](https://www.hpcwire.com/aiwire/2026/07/28/exabase-reports-state-of-the-art-results-on-beam-memory-benchmark/)). **Hindsight** (Vectorize) claimed #1 on BEAM April 2026, later displaced. **memweave** — markdown + SQLite, no vector DB required; FTS5 BM25 + sqlite-vec merged 30/70, SHA-256 content-addressed embedding cache so only changed chunks re-embed, then threshold filter → **exponential temporal decay** → MMR re-rank ([TDS, 2026-04-16](https://towardsdatascience.com/memweave-zero-infra-ai-agent-memory-with-markdown-and-sqlite-no-vector-database-required/)).

## 2. First-party vendor memory

**Anthropic — memory tool (GA) + context editing + compaction.** File-system metaphor with six commands — `view`, `create`, `str_replace`, `insert`, `delete`, `rename` — all rooted at `/memories`. **Client-side:** Claude only *requests* operations; your handler executes against storage you control. ([docs](https://platform.claude.com/docs/en/agents-and-tools/tool-use/memory-tool)) The auto-injected system prompt is instructive: *"ALWAYS VIEW YOUR MEMORY DIRECTORY BEFORE DOING ANYTHING ELSE… ASSUME INTERRUPTION: Your context window might be reset at any moment, so you risk losing any progress that is not recorded in your memory directory."* **Retrieval is directory listing + file read — no embedding step anywhere in Anthropic's first-party memory design.** Numbers: memory + context editing on a 100-turn web search task — **84% token savings, 39% performance improvement** (Anthropic internal) ([announcement](https://www.anthropic.com/news/context-management)). Documented "multisession software development pattern": an initializer session creates progress log + feature checklist + init script; sessions open by reading them; end-of-session update; features marked complete **only after end-to-end verification**. That's your WORK tier, written down by the vendor.

**Claude Managed Agents memory** (public beta 2026-04-23): memory store mounted onto the agent's filesystem, scoped permissions (read-only vs read-write stores), multiple agents concurrently against one store, and **a full audit log of which agent/session wrote each entry**, reviewable in Console. Rakuten: 97% fewer first-pass errors, 27% lower cost, 34% lower latency. Wisedocs: 30% faster verification. ([blog](https://claude.com/blog/claude-managed-agents-memory))

**Claude Code:** `CLAUDE.md` (your instructions) + `MEMORY.md` (Claude's accumulated notes); subagent-scoped memory via a `memory` frontmatter field since v2.1.33 (Feb 2026); idle-time "Auto Dream" pass merging duplicates and replacing stale entries ([docs](https://code.claude.com/docs/en/memory)). **Anthropic removed vector search from Claude Code in May 2025**, citing embedding staleness at scale ([writeup](https://vadim.blog/claude-code-no-indexing/)).

**OpenAI** — memory launched April 2024 as manual saves; April 2025 added **"dreaming"**, a background process curating memories from chat history without explicit saves. The 2026 rollout ships **Dreaming V3**, explicitly targeting *staleness, correctness, and scalability* over multi-year horizons; compute to serve free users cut ~5x ([reverse-engineering writeup](https://llmrefs.com/blog/reverse-engineering-chatgpt-memory)). **Responses API is stateless for identity purposes** — cross-session memory is explicitly the application's job. That's why Mem0/Hindsight sell OpenAI adapters.

**Google** — **Personal Intelligence** launched 2026-01-14 (AI Pro/Ultra, US), connecting Gemini to Gmail, Photos, YouTube, Search. Mechanically: periodic generation of a compressed **user profile / conversation summary**, plus "context packing" per turn ([Android Authority](https://www.androidauthority.com/google-gemini-personal-intelligence-rollout-3632287/)). The distinguishing bet is **data gravity**, not architecture.

**Pattern worth noting:** all three vendors converged on *summarize-and-refresh a compact profile in the background*. OpenAI calls it dreaming, Google calls it personal context, Anthropic calls it Auto Dream. **Nobody's first-party consumer memory is a vector database.**

## 3. Research lines

**HippoRAG / HippoRAG 2** — hippocampal indexing: LLM + KG + Personalized PageRank, mimicking neocortex/hippocampus division of labor. HippoRAG 2 (Gutiérrez et al., 2025) improved entity linking and retrieval ([arXiv 2405.14831](https://www.alphaxiv.org/abs/2405.14831)).

**Two major surveys:**
- *Memory in the Age of AI Agents: A Survey* — 47 authors, Dec 2025 / rev. Jan 2026. Axes: **Forms** (token-level / parametric / latent), **Functions** (factual / experiential / working), **Dynamics** (formation, evolution, retrieval). Argues "long-term vs short-term" is an inadequate frame. ([arXiv 2512.13564](https://arxiv.org/abs/2512.13564))
- *A Survey of Agent Memory in the Second Half* — TMLR with Survey Certification, final 2026-08-04, 60 authors. Axes: **Substrate** (parametric vs external), **Cognitive mechanism** (sensory/working/episodic/semantic/procedural), **Subject** (user-centric vs agent-centric). Thesis: memory is the substrate through which agents self-evolve; **portable, shareable agent skills** are the practical frontier. ([arXiv 2602.06052](https://arxiv.org/pdf/2602.06052))

**Procedural memory / skills as memory** — fastest-moving line in 2026 and closest to your LEARNING tier. Anthropic's Agent Skills format became a de-facto open standard. SkillNet organizes 200k+ skills in one ontology with safety/completeness/executability scoring; ProcMEM learns procedural memory with explicit **activation and termination conditions**; SkillEvolBench measures episodic experience → procedural skill; SkillRevise improves LLM-authored skills using execution traces. ([survey](https://arxiv.org/html/2606.23127v1), [SkillEvolBench](https://arxiv.org/html/2605.24117v1))

**ACE (Agentic Context Engineering)** — Stanford + SambaNova, ICLR 2026. Context as an **evolving playbook** built by generation → reflection → curation with structured *incremental* updates under a "grow-and-refine" principle, explicitly to prevent **context collapse** (repeated rewriting of a memory doc erodes its detail). +10.6% on agents, +8.6% on finance; matches the top production agent on AppWorld with a smaller open model; adapts from execution feedback with no labels. ([arXiv 2510.04618](https://arxiv.org/abs/2510.04618))

**GraphRAG economics collapsed, in GraphRAG's favor.** Microsoft GraphRAG's ~$33,000 indexing cost per large dataset was the standard 2025 objection. **LazyGraphRAG** defers LLM summarization to query time — indexing cost identical to plain vector RAG, matching/beating full GraphRAG on global search at **>700x lower query cost**. LightRAG (HKUDS, EMNLP 2025) does dual-layer graph+vector with incremental updates at roughly embedding cost. 2026 consensus: 50–6,000x cheaper than 2024. ([Graph Praxis](https://medium.com/graph-praxis/the-graphrag-cost-cliff-how-33-000-became-33-in-eighteen-months-be1b0fbe37e4))

**Forgetting and consolidation — most under-solved area, and the most useful concrete finding for you:**
- *Control-Plane Placement Shapes Forgetting* (Dongxu Yang, June 2026) tested **13 architectural configurations** against a 385-case adversarial suite (ForgetEval, MIT). **Deterministic primitives**: handle lexical/temporal deletion but collapse on canonicalization — 5% on identifier obfuscation, **0% cross-lingual**. **Inscribe-time LLM**: fixes canonicalization (100%) but **0% on intent-aware deletion** (prefix collisions, compound facts). **Mutation-time hook**: recovers intent-aware deletion (78–85%), near-universally better (91.7–93.2% overall), at 2.3s/case vs 64–191ms. **Where you put the LLM in the memory pipeline determines which class of forgetting bug you're stuck with.** ([arXiv 2606.15903](https://arxiv.org/abs/2606.15903))
- Naive summarization consolidation loses **~20% of encoded facts** (consistent practitioner report). Production pattern: consolidation every 50–200 episodes via background daemon. Modern systems model forgetting as **decay in accessibility, not deletion**, keyed to relevance, access frequency, temporal pattern. ([FadeMem](https://arxiv.org/pdf/2601.18642), [Always-On Agents survey](https://arxiv.org/pdf/2606.30306))
- *Are We Ready For An Agent-Native Memory System?* (Zhou et al., 2026-06-24) argues no — current systems lack agent-specific design, long-horizon continuity, and integration with decision-making. ([arXiv 2606.24775](https://arxiv.org/html/2606.24775))

**Memory security is now a named attack class.** MINJA (memory injection, NeurIPS 2025, Dong et al.) poisons long-term memory through **normal queries only** — no privileged access — reporting **>95% injection success, ~70% attack success**. The payload persists after the attacker leaves and fires for a different user later. Shared memory across a multi-agent crew means one poisoned agent contaminates every reader. ([explainer](https://futureagi.com/glossary/memory-injection-attack-minja/), [attack & defense](https://arxiv.org/abs/2601.05504), [LTM security survey](https://arxiv.org/html/2604.16548v1))

## 4. Benchmarks — and why the leaderboard is close to worthless

| Benchmark | What it measures | Scale | Status |
|---|---|---|---|
| **LoCoMo** | 1,540 Qs: single-hop, multi-hop, open-domain, temporal | 16k–26k tokens/conv | Widely used, **widely discredited** |
| **LongMemEval (V1)** | 500 Qs incl. knowledge updates, multi-session recall | ~115k tokens | Default serious benchmark |
| **LongMemEval-V2** | Web-agent trajectories (WebArena/WorkArena), 451 Qs, 5 abilities incl. **environment gotchas**, **premise awareness**, multimodal | **25M–115M tokens** | The real 2026 bar |
| **BEAM** (ICLR 2026) | 10 categories incl. abstention, contradiction resolution, knowledge update | **1M and 10M tokens** | Unsolvable by long context — most production-relevant |
| **MemBench** | Factual + reflective; effectiveness, efficiency, capacity | — | Academic |
| **OmniMemEval** | 14 commercial products, 10 datasets | — | Published by MemOS, which wins it |
| **ForgetEval** | 385 adversarial deletion/forgetting cases | — | Narrow but rigorous |
| LoCoMo-Plus, MemSyco-Bench (sycophancy), LifeBench, WorldMemArena, MedMemoryBench | successor/specialist | — | Fragmenting fast |

**Published numbers, labeled by who ran them:**
- Mem0 **self-reported**, April 2026: **92.5 LoCoMo, 94.4 LongMemEval** at ~6.9k tokens/query; **BEAM 64.1 @1M, 48.6 @10M**. Attributed to single-pass extraction treating agent-generated facts as first-class + multi-signal retrieval fusing semantic/keyword/entity scores. Gains **+29.6 temporal reasoning, +23.1 multi-hop**. ([Mem0](https://mem0.ai/blog/state-of-ai-agent-memory-2026))
- MemOS **self-reported**: 88.83 LoCoMo, 89.20 LongMemEval.
- Zep **self-reported**: **75.14% ±0.17 J-score on LoCoMo**, p95 latency 0.632s, vs Mem0's best ~68% — after fixing what Zep says were errors in Mem0's evaluation *of Zep*.
- Exabase M-1, July 2026: 76.9 / 75.0 / 68.0 on BEAM @100K/1M/10M.
- LongMemEval-V2's own paper: simple RAG baseline **42.8%**, plain **Codex agent 69.9%**, best system (AgentRunbook-C, coding agent + workflow manifests) **74.9%**. ([arXiv 2605.12493](https://arxiv.org/html/2605.12493v1))

**The contested part — the important bit.** Zep published a direct methodological attack on Mem0's SOTA claim ([*Lies, Damn Lies, & Statistics*](https://blog.getzep.com/lies-damn-lies-statistics-is-mem0-really-sota-in-agent-memory/)): LoCoMo conversations are 16k–26k tokens, i.e. **trivially inside a modern context window**, so it doesn't test long-term retrieval at all; it omits knowledge-update testing entirely; and the dataset has missing ground truth in Category 5, wrong speaker attribution, multimodal mismatches, ambiguous questions with multiple valid answers. On setup: Mem0 assigned the user role to both speakers, appended timestamps to message text instead of using `created_at`, and ran searches sequentially — inflating Zep's latency. Separately, **Mem0's own LongMemEval number fell to 73.8% under Maximem's independent harness.**

Broader academic criticism: task-disclosed prompting and string-matching metrics **conflate memory fidelity with prompt adaptation and generation style**; these benchmarks assume stationary user intent and unambiguous ground truth, so they cannot see **stale preference reuse, incorrect overwriting of long-term state, or unsafe retention of sensitive information** — the failure modes that actually hurt. ([LoCoMo-Plus](https://arxiv.org/html/2602.10715v1))

**My read:** treat every vendor benchmark number here as marketing. The only numbers I'd act on are ForgetEval's placement results, Chroma's context-rot data, and LongMemEval-V2's finding that **a plain coding agent with file tools (69.9%) beats a RAG memory system (58.6%) by 11 points** on realistic agent-memory tasks.

## 5. The counter-position: against vector DBs and RAG

**Anthropic's official position** ([Effective context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)): *"Rather than pre-processing all relevant data up front, agents built with the 'just-in-time' approach maintain lightweight identifiers (file paths, stored queries, web links, etc.) and use these references to dynamically load data into context at runtime using tools."* Metadata — file hierarchy, naming conventions, timestamps — is itself retrieval signal. Sub-agents return 1,000–2,000 token condensed summaries. They removed vector search from Claude Code citing **embedding staleness at scale**. Notably: they publish **no quantitative support** for the position.

**Manus** ([Context Engineering Lessons](https://manus.im/blog/Context-Engineering-for-AI-Agents-Lessons-from-Building-Manus)): filesystem as *the* context — unlimited, persistent, agent-operable. Two liftable ideas: **restorable compression** (drop a page's content as long as the URL survives; drop a document's body as long as its path survives — never lose information irrecoverably) and **recitation** (constantly rewrite `todo.md` so the plan stays in the model's recent attention span). Runs at millions of users — strongest existence proof against "files don't scale."

**Context rot — the strongest empirical argument for external memory of any kind.** Chroma tested 18 frontier models (GPT-4.1, Claude Opus 4 / Sonnet 4, Gemini 2.5, Qwen3) on extended NIAH. Every model degrades with input length. Degradation is **non-uniform** — models hit cliffs (fine at 32K, collapse at 64K). **Semantic similarity of distractors matters more than length.** All 18 did **better on shuffled haystacks than on logically coherent documents**. A 200K window can show serious loss at 50K. ([Chroma](https://www.trychroma.com/research/context-rot))

**Where grep genuinely loses — the honest data:**
- On Natural Questions, raw grep with query keywords gave "abysmal" accuracy; adding an LLM keyword-generation step **~10x'd performance**. Grep alone is not a retrieval system; grep + an LLM query planner is. ([Nuss & Bolts](https://www.nuss-and-bolts.com/p/on-the-lost-nuance-of-grep-vs-semantic))
- ContextBench (Kuba Rogut, Turbopuffer, AI Engineer Europe, 2026-06-03), 50 tasks on Claude Code: wasted file reads **1 in 3 (baseline) → 1 in 5 (grep) → 1 in 8 (grep + semantic)**. But recall was *higher* for baseline, and grep+semantic was "slightly worse in some cases." No token or latency figures published. Presented by a vector-DB vendor. ([coverage](https://www.startuphub.ai/ai-news/ai-research/2026/claude-code-benchmarking-semantic-search-vs-grep))
- Feb 2026 Amazon Science: **keyword search via agentic tool use reaches >90% of RAG-level performance with no vector database.** A competing May 2026 measurement claims indexed retrieval uses 97% fewer Claude Code input tokens. Cursor publishes that they use vector search *alongside* grep.
- Monigatti's example cuts both ways: semantic search for "GEPA" returned sessions about "Gemma" — embeddings conflate surface-similar tokens, grep would have nailed it. But grep chokes on "movies with animal superheroes." Prescription: **start general, log failures, add specialized tools where they occur.** ([Agentic search for context engineering](https://leoniemonigatti.com/blog/agentic-search-for-context-engineering.html))

**The strongest arguments against your architecture** come from the two vendors with the most to lose, which doesn't make them wrong:

Zep, [*Markdown is not agent memory*](https://blog.getzep.com/markdown-is-not-agent-memory/) (2026-06-23) — concedes markdown is right for "a single agent, one user, a local source of truth, and no compliance," and explicitly praises Claude Code, Letta MemFS, and Manus. Five failure modes: (1) **choosing which files to load is itself retrieval**, and selection accuracy degrades as the file list grows; (2) **a file records what is written, not what it replaced or why** — overwrite destroys history, append creates contradictions, errors compound; (3) **git reconciles text, not meaning** — two commits can each merge cleanly and leave memory logically inconsistent, because git tracks line edits, not fact validity or provenance; (4) **concurrency** — file locking is inconsistent across platforms and breaks on network filesystems; with git you get clean merges that are semantically contradictory ("shipped" in one file, "in review" in another); (5) **governance** — file permissions can't express "this agent, acting for this user, may see these facts," and deletion leaves no retention policy or audit trail.

Mem0, [*Your AI agent's memory is just a file?*](https://mem0.ai/blog/your-ai-agents-memory-is-just-a-file-thats-the-problem) (2026-07-31) — concedes files are right below **~200 static memories, single user**, and for static config and prototyping. Then: 500 memories burns 15,000+ tokens just to load; 10,000 memories blows the context window entirely while selective retrieval stays ~2K tokens regardless of store size; claimed 100x token-cost difference ($90/mo vs $1.80/mo at scale). Plus: no semantic search ("frontend framework" won't match a note about "React to Svelte migration"), no fact-level timestamps, race conditions with documented corruption, no deterministic conflict resolution, no multi-tenancy, and **no forgetting** — signal-to-noise decays monotonically.

## 6. Where a filesystem+ripgrep memory architecture actually loses

Not diplomatic. Ordered by how likely they are to bite you.

**1. Lexical recall fails on paraphrase, and you won't notice.** The real one. Ripgrep finds what you searched for; it cannot tell you the thing you needed is filed under different words. The NQ result — grep-with-query-keywords "abysmal," grep-with-LLM-generated-keywords 10x better — says the fix is query expansion, not a vector DB. Right now, if a memory about "the merge-queue flakiness" is what you need and you grep "CI instability," you get zero hits and the system **fails silently**. A miss looks exactly like an absence. That is the most dangerous property of your architecture, and it worsens monotonically as the archive grows.

**2. Retrieval-by-file-selection degrades as the directory grows — and this is retrieval, whatever you call it.** Your `MEMORY.md` index line + filetree *is* the retrieval index, and its precision is bounded by how well a one-line hook discriminates among N candidates. Zep's point is correct and unglamorous: this works until there are more files than the model can reliably choose between. You have no measurement of where that point is for your store.

**3. No fact-level provenance or supersession.** Git gives you *file* history, not *fact* validity. When a memory says "use `pai -m`" and later "never use `pai -m`," git tells you which line changed when, but nothing knows fact B invalidated fact A, or reconstructs what you believed on 2026-05-01. Your CLAUDE.md is a live demonstration: it accumulates dated operational rules with no invalidation mechanism, so it can only grow.

**4. No forgetting, no decay, monotonic signal degradation.** Nothing in your tiering makes an old learning less accessible. Every rule ever learned competes for attention with every other rule forever — exactly what your BitterPillEngineering skill remediates manually, on demand, by a human. Everyone else automates this. memweave's exponential temporal decay is ~30 lines; you have none.

**5. Concurrency is a real hazard for you specifically, because you run write-agents in parallel.** File locking is inconsistent across platforms; two agents appending to `MEMORY.md` race. Git-per-worktree (Letta's answer) fixes the *textual* race but not the *semantic* one — two clean merges can leave contradictory memories. Your existing rule about staging explicit paths while write-agents are concurrent is a symptom of this gap, not a fix for it.

**6. The write path has no gate.** ForgetEval's finding aims directly at you: deterministic primitives only → 5% on identifier obfuscation, **0% cross-lingual canonicalization**, no intent-aware deletion at all. A mutation-time LLM hook recovers 78–85% of intent-aware deletion and 91.7–93.2% overall at 2.3s/case. You have hooks. You do not have a mutation-time reconciliation hook asking "does this new memory contradict, subsume, or duplicate an existing one?" **Highest-value missing component in your system.**

**7. Context collapse when memory files get rewritten.** ACE's central finding: repeatedly having a model rewrite a memory document erodes detail in ways that look fine each time and are catastrophic in aggregate. Any consolidation you add without incremental, delta-structured updates will silently lose ~20% of facts per pass.

**8. Memory poisoning, and no audit trail of *who wrote what*.** MINJA gets >95% injection / ~70% attack success through normal queries. Your write path is hooks capturing learnings from session content — which includes web pages, repo contents, and subagent output. Anthropic's Managed Agents memory ships a per-entry audit log of which agent and session wrote it, specifically for this. Yours has git blame, which tells you which *process* committed, not which *source* the claim came from. Your own rule that "code comments are claims, not evidence" is this problem one level down, and you keep rediscovering it.

**9. Everything is single-user and local, so several published objections don't apply — say so and move on.** Multi-tenancy, per-user access control, compliance retention, cross-org sharing are the bulk of Zep's and Mem0's argument and are irrelevant to a personal system. Don't let them scare you into a service.

**10. Token cost is real but overstated.** Mem0's $90 vs $1.80/mo assumes you load the whole store every turn. You don't. The honest version for you is **read amplification**: grepping, opening three wrong files, and reading them costs real tokens per session — ContextBench measured that a grep-only agent still wastes 1 in 5 file reads.

## 7. Ideas worth stealing

Ranked by value-per-unit-effort for your system specifically.

**1. A derived index alongside the files, with files still the source of truth. (Highest value.)** Basic Memory's and memweave's design, and it costs you nothing architecturally: SQLite FTS5 (BM25) for ranked lexical retrieval, optionally sqlite-vec for semantic, merged. Copy memweave's write path wholesale: chunk → SHA-256 → embedding cache lookup → embed only changed chunks → insert. Deterministic, LLM-free, cheap, rebuildable from the markdown at any time. **Kills failure mode #1 without giving up a single property you care about.** If you refuse embeddings on principle, BM25 alone gets you ranked recall over 10k files, which ripgrep does not provide at all.

**2. An LLM query-expansion step before ripgrep.** Cheapest possible fix for paraphrase failure, and the measured one (~10x on NQ). Before searching MEMORY/KNOWLEDGE, have a fast model emit 5–8 alternative phrasings and synonyms, then `rg -e` all of them. One `Inference.ts fast` call; directly addresses the silent-miss problem.

**3. A mutation-time reconciliation hook.** ForgetEval's clearest result: the LLM belongs at *mutation* time, not inscribe time. When a hook is about to write a learning, retrieve the k nearest existing memories and force an explicit verdict — `ADD / UPDATE / SUPERSEDE / NOOP` — recording *which memory* was superseded and why. Gives you 78–85% of intent-aware deletion and most of what bi-temporal graphs buy, at markdown cost.

**4. Bi-temporal frontmatter — the cheap 80% of Graphiti.** Add `valid_from`, `valid_until`, `superseded_by`, `source` to memory frontmatter. Never delete a superseded fact; mark it invalid and link forward. You get "what did I believe on date X," contradiction detection, and — critically for your CLAUDE.md — a mechanical way to retire operational rules instead of accumulating them forever. Cost: four YAML keys.

**5. Temporal decay in ranking.** memweave's exponential decay, ~90-day half-life, applied at rank time rather than by deleting anything. Their book-club example is exactly your failure case: without decay a five-month-old answer outranks today's. Decay is a *ranking* operation, so files stay immutable and nothing is lost.

**6. Restorable compression, from Manus.** Never drop information you can't reconstruct. Drop a page body if you keep the URL; drop a file body if you keep the path. Make it an explicit rule for compaction and consolidation so no summarization step is lossy-without-recourse.

**7. ACE-style incremental delta updates, never wholesale rewrites.** When consolidating, emit *deltas* against the existing document under a grow-and-refine rule. Never hand a model a memory file and say "rewrite this better" — documented path to context collapse and ~20% fact loss per pass.

**8. Sleep-time compute / a real consolidation daemon.** You have hooks that fire on session events; you don't have an idle-time process that reorganizes. Letta+Berkeley measured ~5x reduction in test-time compute for equal accuracy and +13–18% accuracy when scaled. Production pattern is a **background daemon every 50–200 episodes**, not on-request, to avoid latency spikes. Anthropic ships this as Auto Dream; OpenAI as Dreaming V3. **You're the only one in this report without it.**

**9. Subagent memory worktrees, from Letta.** You already have EnterWorktree and a one-branch-one-worktree rule. Extend it to memory: each concurrent write-agent gets an isolated memory worktree, merges back through git. Retires your "stage explicit file paths while write-agents are concurrent" workaround. Caveat Zep raises and Letta doesn't answer: git merges text, not meaning — pair with #3.

**10. Provenance-as-source, not provenance-as-commit.** Anthropic's Managed Agents log which agent and session produced each memory. Add a `source:` field recording *where the claim came from* — user statement, tool output, web page, subagent report — and treat "subagent report" and "web page" as lower trust. Structural version of your own rules that comments and agent reports are claims rather than evidence, and your only defense against MINJA-style poisoning through session content.

**11. Skills as a first-class memory tier with activation conditions.** Strongest 2026 research line, and you're one field away: ProcMEM's contribution is that a procedural memory carries explicit **activation and termination conditions**. Your skills have activation triggers; your *learnings* don't. Adding "when does this apply / when does it stop applying" to LEARNING entries turns a growing pile of rules into a retrievable, retirable procedural memory — and gives BitterPillEngineering a mechanical criterion instead of a judgment call.

**12. Recitation.** Manus's `todo.md` trick — rewrite the active plan at the end of context every few turns so it stays in recent attention. Free, and counters the context-rot cliff Chroma measured.

**One thing not to steal:** a hosted memory service. Every governance, multi-tenancy, and compliance argument in Zep's and Mem0's case against files targets a use case you don't have, and Zep already retired self-hosted Community Edition. The parts that do land on you — provenance, supersession, decay, concurrency, semantic recall — are all buildable in your existing substrate in a few hundred lines.
